## Vue d'ensemble

**Fichier :** `src/llm/client.py`

Le projet utilise deux LLMs distincts selon la complexité de la tâche :

<CardGroup cols={2}>
  <Card title="Fast — Groq" icon="bolt">
    **Llama-3.1-8B-instant**

    Utilisé pour les tâches nécessitant vitesse et volume (scoring CVSS sur des dizaines de findings).

    Latence typique : 200–500 ms

  <Card title="Strong — NVIDIA" icon="microchip">

## Configuration

Les clés sont lues depuis `src/.env` via `python-dotenv` :

```env

```

## Interface `LLMClient`

```python
class LLMClient:
    def query(
        self,
        prompt: str,
        system: str = "",
        model: str = "fast"   # "fast" | "strong"
    ) -> str:
        ...
```

Les agents appellent simplement :

```python
# ExploitScorerAgent — tâche rapide
result = self.llm.query(prompt, system=SCORING_SYSTEM_PROMPT, model="fast")

# SemanticAnalystAgent — analyse profonde
result = self.llm.query(prompt, system=SECURITY_SYSTEM_PROMPT, model="strong")

# PatcherAgent — génération de diff
result = self.llm.query(prompt, system=PATCH_SYSTEM_PROMPT, model="strong")
```

## Utilisation par agent

| Agent | Modèle | Raison |
|-------|--------|--------|
| SemanticAnalystAgent | **Strong (70B)** | Raisonnement complexe sur la logique métier |
| ExploitScorerAgent | **Fast (8B)** | Volume élevé, scoring standardisé |
| PatcherAgent | **Strong (70B)** | Génération de code correct et sécurisé |
| TriageAgent | Aucun | Règles déterministes |
| ScannerAgent | Aucun | Outils CLI externes |
| MemorySafetyAgent | Aucun | Binaire Rust externe |
| ValidatorAgent | Aucun | Re-scan Semgrep + diff application |
| ReportAgent | Aucun | Agrégation / sérialisation |

## Gestion des erreurs LLM

Le client capture les erreurs et retourne une chaîne vide. Chaque agent gère le cas `result = ""` avec des fallbacks :

```python
# ExploitScorerAgent — fallback CVSS si LLM échoue
if not llm_result:
    vuln.cvss_score = SEVERITY_CVSS[vuln.severity]
    vuln.is_exploitable = vuln.severity in (Severity.CRITICAL, Severity.HIGH)
```

```python
# PatcherAgent — skip si LLM ne génère pas de diff valide
if not is_valid_diff(llm_result):
    state.errors.append(f"PatcherAgent: invalid diff for {vuln.id}")
    continue
```

## Temperature et déterminisme

Les deux modèles sont configurés avec `temperature=0.2` pour maximiser la cohérence des réponses structurées (JSON, diffs unifiés). Une température trop haute produit des JSONs malformés ou des diffs invalides.

<Tip>
  Si vous observez des erreurs de parsing JSON fréquentes, vérifiez que `temperature` reste ≤ 0.3 dans `src/llm/client.py`.
</Tip>
